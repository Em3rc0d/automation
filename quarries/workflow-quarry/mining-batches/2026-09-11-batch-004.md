## D-01 — B2B Lead Qualification with Voice Calls (VAPI)

Path: `templates/lead-generation/5404-b2b-lead-qualification/workflow.json`
Blob SHA: `8b6ce71a5c16a8484a30919cd96f833651307ea6`

Observed pattern:

```text
Google Sheets row-added lead
→ VAPI outbound call request
→ separate webhook receives VAPI tool-call lead details
→ append/update qualified lead in Google Sheet
→ webhook acknowledgement
```

Useful ideas:
- separates call initiation from asynchronous callback;
- illustrates external AI/voice provider callback pattern;
- stores extracted qualification fields after the call;
- direct fit for a future voice qualification connector.

Hardening/security blockers:
- real Google Sheet document/sheet identifiers are embedded in the export;
- VAPI request body contains placeholder assistant/phone IDs rather than tenant config;
- Authorization header is represented as a literal placeholder field instead of n8n credential storage;
- callback webhook path is fixed and no signature/auth verification is visible;
- no correlation/idempotency key linking original lead → call → callback;
- qualifying state is persisted to Google Sheets instead of ProcessRecord;
- no retry/circuit breaker around voice provider;
- timezone is fixed to Asia/Kolkata;
- no consent/call-policy abstraction for outbound voice use;
- no ExecutionEvent, Incident, AuditEvent or SavingsEvent.

Gate: INSPECTED
Priority: P1 for current launch; P0 pattern if a paying client requires phone qualification.
Decision: retain asynchronous callback/correlation pattern; do not make outbound AI calls part of default LeadFlow.

## D-02 — AI Invoice Agent

Path: `templates/invoice-processing/7905-ai-invoice-agent/workflow.json`
Blob SHA: `d8f1db0d0be20e2aab30a8e9555e54f2061db0c9`

Observed pattern:

```text
Manual run
→ Google Sheets invoice queue
→ filter Pending
→ normalize invoice fields/dates
→ loop
→ AI writes invoice email
→ information extractor splits subject/body
→ CraftMyPDF PDF generation
→ Gmail send with PDF
→ update Google Sheet status Completed
```

Strong reusable ideas:
- explicit Pending → Completed state transition;
- batch processing of invoice queue;
- generated PDF is attached directly to outbound email;
- structured extraction after AI generation is better than using raw free text downstream.

Hardening blockers:
- workflow is manually triggered rather than driven by our process/event contract;
- invoice source-of-truth/status remains Google Sheets;
- real Google Sheet identifier is embedded;
- company identity, address, email, USD currency and due-date rule are hardcoded;
- AI is used to generate deterministic invoice-email copy where a template may be cheaper/more predictable;
- third-party/community node `n8n-nodes-craftmypdf.craftMyPdf` requires supply-chain/licensing review;
- no duplicate-send/idempotency protection;
- Gmail may succeed while status update fails, creating replay risk;
- no approval policy for invoices/value thresholds;
- no platform ProcessRecord/ExecutionEvent/Incident/Audit/Savings integration.

Gate: INSPECTED
Priority: P0 Quote2Cash/Invoice hardening source.
Decision: preserve the queue/batch/PDF/send/state sequence but move truth into our platform and use deterministic templates by default.

## Source E — mlnjsh/n8n-workflows-mega reality check

Repository: https://github.com/mlnjsh/n8n-workflows-mega
Repository license metadata: MIT
Claim: 5,000+ workflows.

Observed structure:
- top-level domain directories exist (`finance-accounting`, `customer-support`, `ecommerce`, etc.);
- `finance-accounting/` contains a large README, not workflow JSON;
- GitHub code search for `extension:json` returned `total_count: 0` at the time of this mining pass.

The finance README is nevertheless rich: it enumerates hundreds of automation specifications with name, trigger, integrations, description and complexity. Examples include invoice creation, overdue reminders, approval routing, duplicate detection, AP/AR, reconciliation and reporting.

Classification:

```text
NOT an 8k-style code corpus
YES a large use-case/specification corpus
```

Action:
- retain permanently in research/knowledge quarry;
- do not count its advertised number as import-ready workflows;
- use it to expand commercial catalog, test scenarios and future template backlog.

This is precisely why mining verifies repository contents instead of trusting descriptions.

## Tooling change caused by this batch

`tools/index_workflow_corpus.py` now computes:

- exact file `sha256`;
- `semantic_fingerprint` after removing volatile n8n export metadata;
- duplicate semantic groups;
- duplicate paths + exact hashes.

Duplicate workflows are **not deleted**. The miner preserves each source/path/hash and uses the fingerprint only to collapse repeated technical review effort.
